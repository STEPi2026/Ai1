# AI① S1-3 실호출 테스트 준비 (2026-11-10)

Backend가 AI①에 **실제 인증 요청**을 보내는 S1-3 단계의 입력 자료다.
**구현을 변경하지 않고, 현재 코드·테스트·실측 기록에서 확인된 사실만** 정리했다.

- 근거: `app/main.py`, `app/schemas.py`, `app/integration/internal_auth.py`,
  `app/integration/backend_adapter.py`, `app/integration/ocr.py`,
  `tests/test_internal_auth.py`, `tests/test_attempt_api.py`
- 이 문서를 만드는 과정에서 **실제 분석·OCR 호출은 하지 않았다**(아래 예시 응답은
  이전 S1-2 점검 때 관측한 값을 그대로 옮긴 것).
- **API Key 값과 개인정보는 이 문서에 없다.** 키는 `<KEY>` 또는 환경변수로만 표기한다.

## 1. 분석 API — URL 경로와 메서드

| 항목 | 값 |
|---|---|
| 메서드 | **POST** |
| 경로 | `/api/v1/attempts/{attempt_id}/analyze` |
| 전체 URL | `https://vividness-pep-unboxed.ngrok-free.dev/api/v1/attempts/{attempt_id}/analyze` |
| 경로 파라미터 | `attempt_id` — Backend가 부여하는 시도 식별자(문자열, 불투명 값) |
| Content-Type | `application/json` (UTF-8) |
| 인증 | 필수 (`X-Internal-Api-Key`) |
| 멱등성 | 같은 `attempt_id` + 같은 본문 → **기존 분석을 그대로 반환**(새 `analysis_id` 없음, `analysis_count` 불변) |
| 충돌 | 같은 `attempt_id` + 다른 본문 → **409** `E_ATTEMPT_CONFLICT` |

관련 경로(참고, 이번 테스트 범위 아님):

| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | `/api/v1/attempts/{attempt_id}/ocr` | 이미지 참조 → OCR (provider 미설정 시 503) |
| GET | `/api/v1/attempts/{attempt_id}/analyses` | 분석 이력 목록 |
| GET | `/api/v1/attempts/{attempt_id}/analyses/{analysis_id}` | 분석 1건 상세 |
| GET | `/api/v1/students/{student_id}/history` | 학생 이력 (Backend 미호출) |
| GET | `/api/v1/students/{student_id}/misconceptions/top` | 오개념 상위 N (Backend 미호출) |
| GET | `/health` | 인증 예외. `{"status":"ok"}` |

## 2. API Key 헤더

| 항목 | 값 |
|---|---|
| 헤더 이름 | **`X-Internal-Api-Key`** |
| 형식 | 값 1개. 앞뒤 공백은 제거되고 비교된다 |
| 서버 설정 | 환경변수 `AI1_INTERNAL_API_KEYS` (쉼표로 여러 개 허용 — 교체 기간 구·신 동시 허용) |
| 비교 방식 | `secrets.compare_digest` (상수 시간, 모든 키와 비교) |
| 값 노출 | 응답·로그에 키/헤더 값이 남지 않는다(오류 메시지는 헤더·환경변수 **이름**만 언급) |
| 현재 키 | 43자, `[A-Za-z0-9-_]` (값 비공개 · 별도 채널 전달) |

헤더가 없거나 일치하지 않으면 **401**, 서버에 키가 아예 설정되지 않았으면 **503**
(fail-closed)이다. **403은 쓰지 않는다.**

## 3. 요청 Body 스키마

`extra="forbid"` — **정의되지 않은 필드는 422로 거절**된다(오타로 옵션이 조용히 사라지지 않게).

| 필드 | 타입 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `problem_id` | string | **필수** | — | 문제 식별자. 저장된 문제가 없으면 본문의 `problem_latex`로 최초 등록한다 |
| `solution_text` | string | **필수** | — | 학생 풀이 원문. 줄바꿈/`→`로 단계 구분 |
| `student_id` | string \| int | **필수** | — | 학생 식별자. 정수는 십진 문자열로 정규화, 문자열은 선행 0 보존, **bool은 422** |
| `problem_latex` | string \| null | 조건부 | `null` | 미등록 `problem_id`일 때 **필수**. 이미 등록됐으면 무시(저장본이 기준) |
| `problem_skills` | string[] | 조건부 | `[]` | 문제의 Skill 목록. 미등록 문제는 **추적 가능한 Skill이 최소 1개** 필요(없으면 422 `E_SKILL_NOT_TRACKABLE`) |
| `engine` | `"rule"` \| `"bkt"` | 선택 | `"rule"` | Knowledge State 엔진 |
| `correct_solution` | object \| null | 선택 | `null` | 정답 풀이. 없으면 단계 정렬 없이 분석 |
| `problem_question_text` | string \| null | 선택 | `null` | 미등록 문제 최초 등록 시에만 저장 |
| `problem_concept_name` | string \| null | 선택 | `null` | 〃 (skill에서 추론하지 않음) |
| `problem_unit_name` | string \| null | 선택 | `null` | 〃 (표시 전용) |

`correct_solution` 객체:

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `solution_id` | string | **필수** | 정답 풀이 식별자 |
| `steps` | object[] (min 1) | **필수** | `{latex_text: string, skill_ids: string[]}` |
| `answer_latex` | string | **필수** | 최종 답 |
| `is_primary` | bool | 선택(기본 `true`) | 대표 정답 풀이 여부 |

### ⚠ `problem_skills`에 넣을 수 있는 코드 (S1-3 핵심 제약)

Backend 코드(`SKL-*`)를 넣으면 AI① 내부 `skill_id`로 역변환한다. **crosswalk에 있는
코드만** 통과하고, 모르는 코드는 **추측 없이 422 `E_UNKNOWN_SKILL_CODE`** 로 거절된다.

| 구분 | 현재 역변환 가능한 코드 |
|---|---|
| 승인(approved) | `SKL-1-004` → `distribution` |
| 후보(provisional) | **없음** (2026-11-10 A2: `SKL-2-037` 은 공식 Seed 밖이라 제거) |
| 그 외 SKL 93개 | **미등록 → 422** |
| AI① 내부 ID 직접 사용 | `linear_equation`, `distribution`, `polynomial_addition` 등 taxonomy의 `bkt_eligible=true` 값 (group node는 422 `E_SKILL_NOT_TRACKABLE`) |

→ **S1-3 테스트는 `SKL-1-004` 또는 내부 ID `linear_equation`을 쓰는 것이 안전하다.**
(나머지 SKL 코드는 매핑 승격 후 사용 가능)

## 4. 정상 응답 스키마

`200 OK`, `AnalyzeAttemptResponse` (`extra="forbid"`).

| 필드 | 타입 | 의미 |
|---|---|---|
| `analysis_id` | string | 저장소가 부여한 분석 식별자(멱등 재요청 시 동일) |
| `attempt_id` | string | 요청 경로의 attempt |
| `problem_id` | string | 문제 식별자 |
| `student_id` | string | 정규화된 학생 식별자 |
| `analysis_status` | `ANALYZED` \| `REVIEW_REQUIRED` \| `UNKNOWN` | 판정 완료 / 일부 미판정 / 판정 불가 |
| `analysis_count` | int ≥ 1 | 이 attempt의 분석 이력 수(멱등 재요청은 증가 안 함) |
| `attempted_at` | datetime (UTC, ISO 8601) | **첫 분석 요청 접수 시각**(완료 시각 아님) |
| `correct` | bool | 오류 미검출 여부 |
| `error_step` | int \| null | 첫 오류 단계(1-based) |
| `first_error_step_index` | int \| null | 명세 필드. `error_step`과 동일 값 |
| `error_type` | string \| null | 오류 유형(`concept_error`/`calculation`/`procedure`/`comprehension` …) |
| `error_subtype` | string \| null | 세부 유형 |
| `skill` | string | 대표(추적) Skill |
| `state` | `mastered` \| `learning` \| `needs_practice` | 관측 후 상태 |
| `mastery` | float | 관측 후 숙련도 |
| `misconception_id` | string \| null | 대표 오개념(AI① 내부 ID) |
| `confidence` | float \| null | 분류 신뢰도 |
| `steps_latex` | string[] | 단계 원문 |
| `valid` | (bool\|null)[] | 단계별 판정 (null=판정 보류) |
| `unrecognized` | int[] | 인식 실패 단계 번호 |
| `step_list` | object[] | `step_no`, `latex_text`, `is_correct`, `status`(`correct`/`error`/`unreviewable`), `skill_ids`, `aligned_solution_step_no`, `unrecognized` |
| `errors` | object[] | 독립 오류 목록(오류 없으면 `[]`) |
| `observations` | object[] | Knowledge 관측(`observation_id`, `attempt_id`, `problem_id`, `student_id`, `skill_id`, `outcome`, `error_type`, `error_id`) |
| `misconception_tags` | string[] | 오개념 태그(내부 ID, 근거 있을 때만) |
| `states` | object | `skill_id → state` |
| `mastery_by_skill` | object | `skill_id → mastery` |
| `misconception_tag` | string \| null | 앱 r48 호환 단수 필드 |
| `official_skill_codes` | string[] | **Backend 승인** SKL 코드. 현재 `SKL-1-004`만 나올 수 있음 |
| `official_misconception_codes` | string[] | **Backend 승인** MIS 코드. 현재 `MIS-1-004`만 |
| `provisional_skill_codes` | string[] | 후보(미승인) 코드. **현재 `[]`** (A2 로 시드 밖 코드 제거) |
| `provisional_misconception_codes` | string[] | 후보 코드. **현재 `[]`** (A2) |

## 5. curl 테스트 예시

키는 환경변수로만 넘긴다(명령 기록·로그에 값이 남지 않게).

```bash
# 0) 준비 (값을 직접 붙여넣지 말고 환경변수로)
export AI1_BASE="https://vividness-pep-unboxed.ngrok-free.dev"
export AI1_KEY="<Backend가 전달받은 43자 키>"
```

### 5.1 정상 분석 (성공 기대)

```bash
curl -sS -X POST "$AI1_BASE/api/v1/attempts/A-S13-001/analyze" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Api-Key: $AI1_KEY" \
  -d '{
    "problem_id": "P-S13-001",
    "problem_latex": "2x=6",
    "problem_skills": ["SKL-1-004"],
    "student_id": "S-S13-001",
    "solution_text": "2x=6\nx=3"
  }'
```

- 기대: `200`, `analysis_status: "ANALYZED"`, `observations` 1건 이상
- `problem_skills`를 `["linear_equation"]`로 바꿔도 동작한다(내부 ID 경로 확인용)

### 5.2 인증 실패 확인 (401)

```bash
curl -sS -o /dev/null -w "%{http_code}\n" -X POST \
  "$AI1_BASE/api/v1/attempts/A-S13-002/analyze" \
  -H "Content-Type: application/json" \
  -d '{"problem_id":"P","student_id":"S","solution_text":"x=1"}'
```

### 5.3 요청 스키마 오류 확인 (422)

```bash
curl -sS -X POST "$AI1_BASE/api/v1/attempts/A-S13-003/analyze" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Api-Key: $AI1_KEY" \
```

### 5.4 미등록 문제에 `problem_latex` 누락 (422)


### 5.8 PowerShell에서 보낼 때

```powershell
$AI1_BASE = "https://vividness-pep-unboxed.ngrok-free.dev"
$AI1_KEY  = "<Backend가 전달받은 43자 키>"
$body = @{
  problem_id    = "P-S13-001"
  problem_latex = "2x=6"
  problem_skills = @("SKL-1-004")
  student_id    = "S-S13-001"
  solution_text = "2x=6`nx=3"
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri "$AI1_BASE/api/v1/attempts/A-S13-001/analyze" `
  -Headers @{ "X-Internal-Api-Key" = $AI1_KEY } `
  -ContentType "application/json; charset=utf-8" -Body $body
```

> `curl`은 Windows 기본 별칭이 `Invoke-WebRequest`다. **`curl.exe`**를 쓰거나 위처럼
> `Invoke-RestMethod`를 쓴다. `-d '...'` 안의 개행은 셸에 따라 깨지므로 파일
> (`--data-binary "@body.json"`)로 보내는 편이 안전하다.

## 6. 오류 응답 형식

두 가지 모양이 있다.

### 6.1 도메인·인증 오류 — `detail`이 **객체**

```json
{"detail": {"code": "E_AUTH_INVALID_KEY", "message": "..."}}
```

| HTTP | code | 발생 조건 | 비고 |
|---|---|---|---|
| 401 | `E_AUTH_INVALID_KEY` | 헤더 없음/불일치 | Backend는 재시도하지 않는다 |
| 503 | `E_AUTH_NOT_CONFIGURED` | 서버에 `AI1_INTERNAL_API_KEYS` 미설정 | fail-closed |
| 422 | `E_REFERENCE_INTEGRITY` | 미등록 `problem_id` + `problem_latex` 없음 | |
| 422 | `E_UNKNOWN_SKILL_CODE` | crosswalk에 없는 `SKL-*` 코드 | 기본 Skill로 치환하지 않음 |
| 422 | `E_UNKNOWN_SKILL` | taxonomy에 없는 내부 skill_id | |
| 422 | `E_SKILL_NOT_TRACKABLE` | 추적 가능한 Skill 없음 / group node만 | 아무것도 저장하지 않음 |
| 422 | `E_UNRECOGNIZED` | 모든 단계 판정 불가 | `detail.analysis_status:"UNKNOWN"` 포함 |
| 422 | `E_UNVERIFIABLE` | 동치 판정 불가 | 〃 |
| 422 | `E_EMPTY_SOLUTION` | `solution_text`가 비어 있음 | |
| 413 | `E_INPUT_TOO_LARGE` | 문제식 2000자 / 풀이 2만자 / 단계 30개 초과 | 상한 상향 금지 |
| 409 | `E_ATTEMPT_CONFLICT` | 같은 `attempt_id` + 다른 본문 | 이력 덮어쓰기 없음 |
| 409 | `E_RESOURCE_CONFLICT` | 등록된 문제/정답 풀이와 요청이 불일치 | |
| 409 | `E_SOLUTION_PROBLEM_MISMATCH` | 정답 풀이가 다른 문제 소속 | |
| 404 | `E_ATTEMPT_NOT_FOUND` | (조회 API) attempt 미존재 | analyze 경로 아님 |
| 422 | `E_INVALID_BACKEND_ID` | `attempt_id`/`student_id` 정규화 실패 | |
| 503 | `E_OCR_NOT_CONFIGURED` | OCR provider 미설정 | OCR 경로 |
| 429 | `E_OCR_USAGE_LIMIT_REACHED` | 로컬 호출 예산 소진 | 재시도 대상 아님 |
| 422 | `E_OCR_IMAGE_FETCH_FAILED` / `E_OCR_UNSUPPORTED_IMAGE` | 이미지 다운로드 실패 / 미지원 형식 | URL 미노출 |
| 502 | `E_OCR_PROVIDER_ERROR` | provider 호출 실패 | |
| 503 | `E_OCR_API_DISABLED` / `E_OCR_AUTH_FAILED` / `E_OCR_BILLING_REQUIRED` | GCP 설정 문제 | |

실제 관측 예(과거 점검):

```json
{"detail":{"code":"E_AUTH_INVALID_KEY",
 "message":"인증에 실패했습니다. 유효한 X-Internal-Api-Key 헤더가 필요합니다."}}

{"detail":{"code":"E_REFERENCE_INTEGRITY",
 "message":"등록되지 않은 problem_id: 'tunnel-smoke-1' (problem_latex 필요)"}}

{"detail":{"code":"E_SKILL_NOT_TRACKABLE",
 "message":"Knowledge State 추적 대상이 아닌 skill입니다 (bkt_eligible=false): '(없음)'"}}

{"detail":{"code":"E_UNRECOGNIZED",
 "message":"모든 풀이 단계를 인식하지 못했습니다. 직접 입력으로 다시 시도해 주세요.",
 "analysis_status":"UNKNOWN"}}
```

### 6.2 요청 스키마 검증 오류 — `detail`이 **배열**

Pydantic/FastAPI 기본 형식이다(필드 누락·타입 오류·`extra` 필드).

```json
{"detail":[
  {"type":"missing","loc":["body","problem_id"],"msg":"Field required","input":{}},
  {"type":"missing","loc":["body","student_id"],"msg":"Field required","input":{}}
]}
```

→ Backend는 **`detail`이 객체인지 배열인지 분기**해야 한다(객체면 `code`, 배열이면 검증 오류).

## 7. S1-3 성공 판정 기준

| # | 확인 | 기대 |
|---|---|---|
| 1 | 키 없이 `/health` | 200 `{"status":"ok"}` |
| 2 | 키 없이 analyze | 401 `E_AUTH_INVALID_KEY` |
| 3 | 키 있음 + 정상 본문 | 200, `analysis_status:"ANALYZED"` |
| 4 | 같은 본문 재요청 | 같은 `analysis_id`, `analysis_count` 불변 |
| 5 | 다른 본문 같은 attempt | 409 `E_ATTEMPT_CONFLICT` |
| 6 | `problem_skills` 누락(신규 문제) | 422 `E_SKILL_NOT_TRACKABLE` |
| 7 | 등록된 SKL 코드(`SKL-1-004`) | 200 (역변환 성공) |
| 8 | 미등록 SKL 코드(예: `SKL-1-002`) | 422 `E_UNKNOWN_SKILL_CODE` |
| 9 | 서버 로그에 키·URL·풀이 원문 | **없음** (O-06) |
| 10 | OCR 경로 | 503 `E_OCR_NOT_CONFIGURED`, Vision 호출 0회 |
