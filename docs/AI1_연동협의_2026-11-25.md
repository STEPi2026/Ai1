# AI① 연동 협의 결과 — AI② 튜터 확장 · Backend (2026-11-25)

- 기준일: **2026-11-25**
- 범위: **문서·계약 확인만.** 이 협의로 코드·서버·API는 변경하지 않았다.
- 관련 문서: `docs/AI1_판정한계_목록.md` §5 · `docs/AI1_배포기록_2026-11-23.md` §11 ·

## 1. 요약

- AI②가 학생 반응에 따라 학습 전략을 바꾸는 **튜터 에이전트**로 확장된다.
- AI②가 요청한 7개 항목(분석 상태, 정오답, 풀이 완료, 실제 관측, 보류 사유,
  최초 오류/오류 유형/오개념, 승인 공통 코드)은 기존
  `POST /api/v1/attempts/{attempt_id}/analyze` 응답으로 **모두 충족**된다.
- **신규 API 없음. 응답 필드 추가 없음.**
- Backend 회신으로 아래가 확정됐다.
  - `observations[]` ↔ `error_id` 연결을 사용한다.
  - `analysis_status`를 1차 기준으로 본다.
  - 부분 풀이(`final_answer_present=false`)와 판정 보류(`REVIEW_REQUIRED`)를 오답에서 제외한다.
  - 공통 코드는 기존대로 **Backend 승인 binding만** 사용한다.
  - `confidence`는 정확도가 아닌 **규칙 기반 참고값**으로 처리한다.
- structured OCR provider는 **deferred(2026-11-24)** 이며, 사진 풀이는 힌트용으로만 쓴다.

## 2. 확정 사항

| 항목 | 확정 내용 |
|---|---|
| 신규 API | 불필요. 기존 `/analyze` 계약 유지 |
| 1차 판단 기준 | `analysis_status` (`ANALYZED` / `REVIEW_REQUIRED` / `UNKNOWN`) |
| 정오답 | `correct` — ANALYZED에서만 `true`/`false`, 그 외 `null` |
| 부분 풀이 | `final_answer_present=false`는 오답이 아니라 **풀이 미완료** |
| 판정 보류 | `REVIEW_REQUIRED`는 오답·오개념·숙련도 갱신 대상에서 제외 |
| 실제 관측 | `observations[]` + `error_id`로 `errors[]`를 연결 |
| 다중 오류 | Skill별 대표 1건만 `observations`에 붙고, 전체는 `errors[]`에 보존 |
| 공통 코드 | `official_*`는 참고용. 숙련도 근거는 **Backend 승인 binding** |
| confidence | 규칙 기반 참고값(0.75~0.9). 정답·보류는 `null`. 정확도 아님 |
| Concept | AI①은 만들지 않음. Backend 승인 매핑이 담당 |
| 문제 원문 | `/analyze` 응답에 echo하지 않음. Backend가 보관·전달 |
| 숙련도 저장 | AI② 갱신안 → Backend 저장. AI① `mastery`는 참고값 |
| 영상 검색·추천 | AI①은 수행하지 않음 |

## 3. AI② 판단 규칙

### 3.1 `analysis_status` 우선

| 상태 | 허용 | 금지 |
|---|---|---|
| `ANALYZED` | `correct` / `final_answer_present` / `errors` / `observations`로 행동 선택 | — |
| `REVIEW_REQUIRED` | 확인 질문, 재촬영, 직접 입력 보정 | 오답 단정, Skill/오개념 진단, 숙련도 갱신, `step_list`의 `is_correct=false`를 힌트 근거로 사용 |
| `UNKNOWN` | 오류 응답으로 처리, 재시도·수동 입력 안내 | 정상 payload 재구성, 오답 처리 |

- `REVIEW_REQUIRED`는 `correct` / `final_answer_present` / `error_step`가 `null`,
  `errors` / `observations`가 `[]`다.
- `REVIEW_REQUIRED`인데 `review_reasons=[]`인 경우가 있을 수 있다. 이때도 보류다.
- `review_reasons` 코드 4종: `solution_block_notation`, `function_notation_in_solution`,
  `equation_line_in_expression_mode`, `expression_problem_not_expression`.

### 3.2 정오답 × 풀이 완료

| `correct` | `final_answer_present` | 해석 | AI② 권장 |
|---|---|---|---|
| `true` | `true` | 오류 미검출 + 최종답 있음 | 다음 문제·심화. 오개념 개입 없음 |
| `false` | `true` | 오류 + 최종답 있음 | `errors[0]` 기준 개념 복습·힌트·확인 질문 |
| `false` | `false` | 오류 + 최종답 없음(부분 풀이) | 풀이 완성 유도. 오개념 단정 보류 |
| `null` | `null` | 판정 보류 | 확인·보정 요청만 |

- `correct=true`는 "오류가 검출되지 않음"이지 완전 검증이 아니다.
  숙련도 상승의 강한 근거로 쓰지 않는다.

### 3.3 `observations` ↔ `error_id`

- `observations[]`는 Skill 단위 관측이다: `skill_id`, `outcome`, `error_type`, `error_id`.
- `error_id`로 `errors[]`의 `evidence_latex` / `error_type` / `misconception_ids`를 읽는다.
- 같은 Skill에 오류가 여러 건이면 `observations`에는 **대표(첫) `error_id` 하나**만 붙는다.
  전체 오류는 `errors[]`를 기준으로 한다.
- `observations`가 빈 배열일 수 있다. 대표 Skill·`errors`·`step_list`로 대체하지 않는다.

### 3.4 공통 코드·confidence

- `official_skill_codes` / `official_misconception_codes`는 승인된 매핑만 나간다. 미승인은 `[]`.
- `provisional_*`는 승인 전 후보이며 판단 근거로 쓰지 않는다.
- `confidence`(0.75~0.9)는 규칙 기반 참고값이다. 임계값·정확도로 단정하지 않는다.

### 3.5 금지 목록

1. `REVIEW_REQUIRED` / `UNKNOWN`을 오답으로 저장
2. `step_list`의 `is_correct=false`만으로 오류 단정
3. `observations`가 빈 경우 대표 Skill로 대체
4. `official_*` / `provisional_*`를 숙련도 근거로 사용
5. `confidence`를 정확도·신뢰 임계값으로 사용
6. 같은 Skill의 다중 오류를 1건으로 축약
7. AI① `mastery`를 최종 숙련도로 사용

## 4. Backend 책임

| 항목 | 내용 |
|---|---|
| Concept 도출 | 승인된 Skill–Concept 관계로 도출. AI②에는 `{source_skill_id, concept_id, mapping_approved}` 형태 권장 |
| 문제 원문 | `problems` 레코드에서 AI② payload에 첨부 |

| 저장 | `analysis_id` / `analysis_count` / `errors[]` / `observations[]` / `official_*` 보존 |
| 숙련도 | AI② 갱신안 저장, AI① `mastery`는 참고값 |
| 영상 | 검색·추천 담당(AI① 미수행) |

- AI①은 MySQL에 직접 접근하지 않는다.

## 5. OCR·사진 흐름

- 현재 OCR은 Google Vision `raw_text`만 제공한다: `problem=null`, `solution_steps=[]`,
  `layout_detected="unknown"`, `layout_mismatch=null`.
- 따라서 문제/풀이 자동 분리는 지원하지 않는다.
- 권장 흐름:
  1. APP 사진 → Backend 저장
  2. Backend → AI① `POST /ocr` (`raw_text` 수신)
  3. Backend/학생이 문제·풀이 텍스트 확인·보정
  4. Backend → AI① `/analyze` → 결과 저장 → AI② 전달
- OCR 결과는 정답 판정·숙련도 갱신에 사용하지 않는다.
